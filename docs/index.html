01What it does

Forgot the password to a wallet export? Recover it on your own machine — no uploads, no third parties, no phone home.

🔓

Recovers the password

Built for the password-protected .json backups the Trust Wallet app exports when you back up a wallet.

🧂

Both KDFs supported

scrypt (Trust Wallet default) and PBKDF2-HMAC-SHA256, both verified against the keystore's MAC — zero false positives.

🧠

Three attack modes

Explicit guesses, dictionary wordlists with smart mutations (digits · years · leetspeak…), and brute force — combinable.

⚙️

All cores, live stats

Parallel across your CPU with progress, rate and ETA. Safe to Ctrl-C any time. Runs on plain Python 3.9+, no install needed.

✅

Proven found

Found keys are cross-checked against the wallet's Ethereum address before reporting success — private keys and mnemonic (“cloud backup”) files alike.

🚀

GPU bridge

One command exports the keystore in hashcat format for GPU-powered cracking (modes 15600 / 15700).

Also ships as a complete suite: trustwallet_backup_inspect · verify · decrypt · recover + trustwallet2hashcat, plus --batch to scan an entire folder of backups. Legacy backups with an empty salt (which hashcat cannot load — issue #4338) are recovered natively.

02How it works

Every candidate password must pay the same KDF cost — that's what makes guessing slow by design. The check itself is cryptographically exact.

1 · Derive
scrypt / PBKDF2(password)
→
2 · Verify MAC
Keccak-256(key[16:32] ‖ ciphertext)
→
3 · Decrypt
AES-128-CTR → private key / phrase
→
4 · Confirm
address == stored address (BIP39/BIP44)

Verified against backup files in the exact layout Trust Wallet's open-source core writes — including mnemonic cloud backups, whose recovery phrase decrypts to the published test address 0x9858EfFD232B4033E47d90003D41EC34EcaEda94.

Why no false positives?

The MAC (message-authentication code) stored in the file can only match if the derived key is byte-identical — which means the password is byte-identical. A match is mathematical proof, not a guess.

Why is it slow?

KDF parameters (e.g. scrypt n=262144) are set so each attempt costs 50–150 ms of real CPU+memory work. Nobody can bypass that — instead, choose smarter candidates and parallelize your cores.

03Using it

One file, zero dependencies for PBKDF2 wallets. Copy-paste these into your terminal.

Quick check of a remembered password

$ twrecover -k wallet.json -p "mybirthday123"

Dictionary attack with mutations

# words.txt contains:  sunflower   dragon   karen97   ...
$ twrecover -k wallet.json -l my-words.txt -r medium
[ 32.4%] 1,234,567/3,812,400 candidates | 141/s | ETA 5h 03m
[+] password found in wordlist (2h 11m)
Password: sunFlower42!

Brute force a known shape

$ twrecover -k wallet.json -a abcdefghijklmnopqrstuvwxyz0123456789 \
           --min-length 4 --max-length 4

Hand off to a GPU (hashcat)

$ twrecover -k wallet.json --export-hashcat wallet.15700
$ hashcat -m 15700 wallet.15700 wordlist.txt

Scan a whole folder

$ twrecover --batch ~/backups -l words.txt -r basic
[+] batch done: 2 of 3 file(s) recovered

Exit codes: 0 found · 1 not found · 2 usage/keystore error · 130 interrupted. Full reference in the README.

05Performance & GPU

Know before you burn compute. --benchmark measures your exact machine and prints per-worker RAM usage.

Keystore KDFms/attemptguesses/s (1 core)
scrypt n=16384 (Trust default)~50–90~11–20
scrypt n=262144~120–160~6–8
pbkdf2 c=100000~40~25

Multipliers: all-core throughput ≈ single-core rate × cores. When that isn't enough, --export-hashcat produces the exact hashcat "Ethereum Wallet" format (verified against hashcat's own module source), so a GPU can take over with hashcat -m 15700 / -m 15600.
